# v0.8.12 — ChatGPT 工具循环修复 + 若干稳健性改进

本次亮点速览：

1. **ChatGPT 多消息流适配** —— 修复「AI 输出了 estrix 代码块，却提示未检测到工具调用」以及「工具只调一次就不调了」的问题。（由 **@brownie19850318** 的 PR #49 贡献）
2. **工具执行遮罩支持取消** —— 工具执行期间遮罩显示「停止」按钮，长任务可中途取消。
3. **输入框填入更可靠** —— contenteditable 平台改用 `execCommand('insertText')` + 读回校验，修复合成粘贴事件被站点拒收导致的填入失败。
4. **压缩后上下文交接** —— 长会话压缩后提示 AI 主动读文件补全上下文，避免盲目相信残缺摘要。
5. **关窗释放渲染进程** —— 修复窗口关闭时子视图渲染进程不释放的问题（孤儿进程 + 内存泄漏）。

> 特别感谢本版的外部贡献者：**@brownie19850318**（PR #49）。

## 💬 ChatGPT 多消息流适配

ChatGPT 网页版在部分场景下，会在**同一条 SSE 流**里先后下发多条 assistant 消息，中间夹一条纯文字说明。此前按「某条消息 `finished`」上报并随即锁定，导致其后才到达、真正含 estrix 代码块的消息被永久丢弃 —— 表现为「AI 输出了代码块，却提示未检测到工具调用」。

本次修复：

- 新增 `endTurn` 状态，区分「**消息级完成**」与「**整轮结束**」；仅 `end_turn === true` / `[DONE]` 时立即上报，否则等流关闭兜底 —— 中间消息不再提前结束本轮
- 新增 `overwriteText()`：新内容不含 estrix 块、而当前正文含块时不覆盖，避免正文被顶掉
- XHR 分支同步（`xhr-finished-frame` → `xhr-end-turn`）

（**@brownie19850318**，PR #49）

## 🛑 工具执行遮罩支持取消

工具调用执行期间，遮罩上新增「**停止**」按钮：

- 点击可取消当前回传（已执行的代码块结果保留，未执行的代码块不再执行）
- 长任务（如 `runAgent`）不再只能干等

---

## ⌨️ 输入框填入更可靠

contenteditable 平台（ChatGPT 等）的填入逻辑改用 `document.execCommand('insertText')`：

- **修复**：合成 `ClipboardEvent('paste')` 是 `isTrusted=false` 的事件，ProseMirror 等会拒收 → 填入静默失败
- **新增读回校验**：写入后校验内容长度（去空白后 ≥ 期望的 90%），失败即返回 false，避免"以为填好了实际没填"

---

## 📋 压缩后上下文交接

长会话压缩后，新会话只有摘要上下文，AI 容易盲目相信它。现在压缩后会注入一条**上下文交接提示**，要求 AI：

1. 读取项目文档/代码，了解项目现状与进行中的任务
2. 核实摘要中的关键结论在文件/代码里是否真实成立
3. 明确当前进度与下一步
4. 最后输出一句「上下文交接已完成」

## 🪟 关窗释放渲染进程

窗口为「壳 `BrowserWindow` + AI 页 `WebContentsView`（+ 懒加载 harness 视图）」双层结构。Electron 的 `win.close()` 只销毁壳窗口的 webContents，挂在 `contentView` 上的子 view **独立持有渲染进程、不会被连带销毁** —— 每个窗口关闭后留下孤儿渲染进程。

本次修复：关窗时显式 `removeChildView` + `webContents.close()`，真正释放子视图渲染进程（实测 120 个任务 = 120 孤儿进程 + 275 MB 未释放）。
