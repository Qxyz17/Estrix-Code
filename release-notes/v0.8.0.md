## ✨ 新增

### 子代理（对齐 Claude Code）· 0.8.0

**什么是子代理**：主对话可以把一件活**委派**给一个"独立分身"去干——它在**全新的上下文**里工作，
干完只把**结果摘要**交回来，过程的翻找、试错都不占用主对话的"脑子"。

**好处**：① **上下文隔离**——大范围搜索、分析不再把主对话塞满，长对话更不容易卡；
② **专门化 + 工具限制**——可以让某个分身只读文件、或只跑测试。

**怎么用**（纯文件，无需界面操作）：

1. 在项目里创建 `.estrix/agents/<代理名>.md`，或用户级 `~/.estrix/agents/<代理名>.md`
2. 文件开头写元数据（YAML frontmatter）：

```markdown
---
name: explore
description: 只读探索代码库：大范围搜索、定位、分析代码结构。不修改任何文件。
tools: read, readLines, glob, grep
maxTurns: 20
---

（这里写代理正文：它的角色、工作方式、输出格式……）
```

3. 主对话用 `runAgent(name, task)` 调用它

**自带 8 个现成代理**，开箱即用：

- **通用**：`explore`（只读探子）、`code-reviewer`（代码审查）、`test-runner`（跑测试+查原因）
- **本项目专用**：`arch-guard`（查架构违规）、`tool-smith`（加工具）、`build-doctor`（查构建问题）、
  `req-writer`（写需求档案）、`hook-surgeon`（改 hook）

**刷新代理**：对话已开始时新增了代理？点覆盖层面板的「**刷新技能与代理**」按钮，AI 立刻就能感知。

**兼容 Claude Code**：代理格式对齐 Claude Code 的 subagents 机制。

## 🔧 改进

- **「今日窗口」统计口径修正** · 0.8.0：以前它把每一轮的**完整上下文**都累加进去，越聊数字越离谱
  （两个窗口能显示十几亿）。现在改为**只累加当天新增**的部分，过了午夜自动归零。
  旧口径产生的错误数据会**自动清理**。
- **系统总累计不再虚高** · 0.8.0：子代理和主窗口共用一个登录态，以前它俩的用量会被重复记账。
  现在子代理的用量不计入系统总量。
- **代理文件解析更稳** · 0.8.0：`name` 写成一堆空白、`maxTurns` 填了非法字符等情况，现在都能正确处理。

## 🐛 修复

- **子代理窗口白板** · 0.8.0：子代理窗口在"新对话"页会被误判为首页，把整个面板藏起来，
  看着像什么都没设置。现在正常显示完整面板。
- **子代理窗口收不到回复** · 0.8.0：修复了一个让子代理窗口无法正常工作的初始化问题。
