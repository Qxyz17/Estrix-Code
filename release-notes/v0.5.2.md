# Estrix Code v0.5.2 Release Notes

**发布日期：** 2026-09-17

## 🎯 本次更新重点

本次更新带来**请求失败自动重试**与**工具循环看门狗**两大稳定性能力：当 AI 对话因网络错误、服务端异常或流中断而失败时，应用会自动重发提示词让 AI 继续；当 AI 在工具调用循环中长时间没有响应时，也会自动催促继续。此外修复了「用户主动停止被误判为失败并触发重试」和「inject_js 无法处理多语句代码」两个问题。

---

## ✨ 新增功能

### 请求失败自动重试
AI 对话请求失败时（网络错误 / 非 2xx / 流中断），按配置间隔自动重发提示词，触发 AI 重新回答：
- **普通失败**：默认 4~10 秒随机间隔、最多 10 次
- **操作频繁（429）**：默认 60 秒间隔、最多 20 次（独立计数）
- 次数填**负数表示不限次**；一旦成功回复即重置计数
- 失败后弹出**倒计时浮层**，可随时点「取消」中止重试
- 压缩上下文进行期间自动暂停重试，避免污染摘要请求

### 工具循环看门狗
AI 进入工具调用循环后，若某一轮发出消息却迟迟等不到回复（AI 卡住/中断），自动发送「请继续」提示词催促：
- 超时时间默认 **300 秒**、默认催促 **3 次**（可配置，负数=不限次）
- **工具执行期间不监控**（长时间命令如 npm install 不会被误判）
- **会话切换自动失效**：切到别的对话后，看门狗立即重置，不会打扰新会话
- 压缩上下文期间同样自动暂停

### 设置弹窗
新增集中设置面板，可配置：
- 失败自动重试开关、普通/操作频繁的间隔与次数、重试提示词
- 工具循环看门狗的超时时间、提示词、催促次数
- 发送延迟
- 时间单位统一为**秒**（更直观）
- 新增「**恢复默认**」按钮，一键还原全部配置

### 内置平台容错加载
单个内置平台文件缺失或损坏时，不再拖垮整个应用启动，其余平台仍可正常使用。

## 🐛 问题修复

### 修复用户主动停止被误判为失败并触发重试
此前，用户手动点击「停止生成」后，部分情况下 SSE 流未下发明确状态，导致被判定为请求失败，进而触发自动重试、打扰用户。
本次通过**拦截 DeepSeek 的 stop_stream 请求**作为「用户停止」的可靠判据，彻底解决该问题。

### 修复 inject_js 工具无法处理多语句代码
此前 inject_js 通过「是否以 return 开头」决定包装策略，导致以下输入解析失败：
- 多语句：`const x=1; return x;`
- 条件返回：`if (...) return ...`
- 顶层 await：`await ...; return ...`
本次改用**两遍语法探测**（先尝试按表达式解析，失败则回退为 async 函数体），既保留原有表达式/IIFE 用法，又支持任意语句体与顶层 await。

## 🔧 内部改进

- **类 AOP 日志工具**（`src/utils/with-log.js`）：可为模块方法自动注入入参/出参日志，便于排查问题
- 重试引擎增加**会话校验**：旧会话的延迟失败不再误触发当前会话的重试
- 新增单元测试 **60+ 项**（重试引擎、拦截观察器、看门狗），测试总数达 285 项
