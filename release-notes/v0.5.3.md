# Estrix Code v0.5.3 Release Notes

**发布日期：** 2026-09-18

## 🎯 本次更新重点

本次更新带来**附件上传工具**与**MCP 能力全面增强**：AI 现在可以把本地文件（PDF、Word、Excel、PPT、图片等）作为附件主动上传到对话；同时大幅改进 MCP 集成——初始化提示词会列出已启用的 MCP server，不再阻塞等待连接，并修复了并发连接竞态与截图产物定位问题。

---

## ✨ 新增功能

### 附件上传工具（attach_file）
AI 可将本地文件作为附件上传到当前对话输入框（不自动发送）：
- **主动判断**：当需要基于无法用 read 读取的文件（PDF、Word、Excel、PPT、图片等二进制文件）作答，或需要把文件交给用户看时，自动使用，无需用户明确说「上传」
- 上传后文件随下一条消息发出，AI 即可基于其内容作答
- 仅支持已存在的单个文件，大小上限 30MB
- 自动按扩展名推断 MIME 类型

### 附件上传间隔设置
设置面板新增「附件上传间隔」，默认 0.5~1 秒（可配置）：
- 触发上传后先等待该时长再检测附件是否出现
- 保留兜底轮询，页面渲染慢时不会误判失败

### 「卡住了?点我」快捷按钮
原「手动解析」按钮改为「卡住了?点我」：点击即向 AI 发送「刚才卡住了请继续 爱你哦」，一键催促卡住的 AI 继续。

## 🔧 MCP 集成增强

### 初始化提示词注入 MCP server 列表
初始化项目时，系统提示词会列出**已配置且启用**的 MCP server（含连接状态与工具数），AI 无需先查询即可知道有哪些 MCP 可用。

### 修复 MCP 章节从未注入的问题
此前 4 个提示词模板均缺少 `{{MCP_SECTION}}` 占位符，导致 MCP 章节虽已组装却从未插入提示词。本次补齐占位符，MCP 能力说明真正生效。

### 初始化不再阻塞等待 MCP 连接
此前初始化项目时会同步等待 MCP 连接最多 8 秒。现改为**后台异步连接**，提示词先按当前状态生成——未连接的 server 标注「未连接」，AI 后续调用时按需连接，初始化更迅速。

### 修复 MCP 并发连接竞态
启动与初始化可能同时触发同一 server 的连接，导致重复 spawn 子进程（stdio 类型）与连接泄漏。现通过 in-flight Promise 缓存复用进行中的连接，确保只连接一次。

### MCP 默认工作目录
stdio 类型的 MCP server 现在有确定的工作目录：
- **优先**：程序目录下的 `mcp-cwd`（卸载/删除程序目录时一并清理）
- **兜底**：程序目录不可写（如 Program Files 安装、macOS）时回退到用户数据目录 `mcp-cwd`
- 覆盖各平台、各安装方式（ZIP/Portable/NSIS），确保始终可用

### AI 可定位 MCP 产物
提示词注入 MCP 工作目录，并说明 MCP 工具返回的相对路径（如截图、下载）实际位于该目录下，AI 可用绝对路径读取或上传这些文件。此前 AI 拿到相对路径却不知道基准目录，无法定位产物。
