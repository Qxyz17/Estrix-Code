# Rules（规则）配置与使用

> 规则让 AI **只在读相关文件时**看到对应的项目约束。对齐 Claude Code 的 `.claude/rules/` 机制。

## 一、它是什么

规则是带 frontmatter 的 Markdown，放在约定目录下。分两种：

| 类型 | 何时生效 |
|---|---|
| **有 `paths`** | 只在 AI **读（read）匹配文件**时注入 |
| **无 `paths`** | 初始化时注入（**始终适用**，同 ESTRIX.md 待遇） |

**核心价值**：项目大了，规则多了——不必把所有约束一股脑塞给 AI。**改 infra 层的代码，才给 infra 的规矩**；改前端，才给前端的。

## 二、目录约定

| 作用域 | 路径 | 说明 |
|---|---|---|
| **项目级** | `<项目根>/.estrix/rules/<name>.md` | 随仓库走，团队共享 |
| **用户级** | `~/.estrix/rules/<name>.md` | 所有项目通用 |

- 扫描 rules 目录下的 `.md` 文件（一层）
- **同名规则都生效**（用户级 + 项目级不覆盖，靠**路径**区分）

## 三、规则文件格式

```markdown
---
name: api-rules
paths:
  - "src/api/**/*.ts"
  - "src/routes/**/*.ts"
---

# API 开发规则

- 所有接口必须校验入参
- 使用统一的错误响应格式
```

### frontmatter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 否 | 规则名。缺省取**文件名** |
| `paths` | 否 | 适用路径（glob 数组）。**省略 → 始终生效** |

- `paths` 支持 `**`（跨层级）、`*`（单层）、`{}`（大括号，如 `src/**/*.{ts,tsx}`）
- 相对路径基于**项目根目录**

## 四、两种规则的注入方式

### 有 `paths`：AI 读到匹配文件时注入

| 命中次数 | AI 收到 |
|---|---|
| **首次** | 规则**全文** + 规则文件路径 |
| **之后** | 规则**名 + 路径**（提示 AI 需要时自己 `read`） |

**去重**：同一条规则在**同一个对话**里只注入一次全文（换新对话会重新注入）。
**注入位置**：拼在工具结果**开头**（截断时不会被切掉）。

**AI 实际看到的示例**（读 `src/api/user.ts`）：

```
【规则「api-rules」｜路径 C:\项目\.estrix\rules\api-rules.md】
# API 开发规则
- 所有接口必须校验入参

<path>src/api/user.ts</path>
...文件内容...
```

### 无 `paths`：初始化时注入

无 `paths` 的规则在**初始化项目**时注入到系统提示词的「**## 项目规则**」章节——和 `ESTRIX.md` 一样，**始终适用**。

## 五、完整示例

`.estrix/rules/test.md`（读测试文件时才生效）：

```markdown
---
name: test
paths:
  - "test/**/*.js"
---

# 测试规则

- 只写真实集成测试，不写深 mock
- 优先覆盖失败路径
```

`.estrix/rules/global.md`（无 `paths`，始终生效）：

```markdown
---
name: global
---

# 通用规则

- 代码注释用中文
- 提交信息遵循 Conventional Commits
```

## 六、与 Skill / Agent 的区别

| | Rules | Skill | Agent |
|---|---|---|---|
| **本质** | 项目**约束**（何时遵守） | 领域**流程/知识** | **独立上下文**的子对话 |
| **触发** | 读匹配文件时（`paths`） | AI 判断任务相关时 `read` | `runAgent` 委派 |
| **注入** | 工具结果 / 系统提示词 | 系统提示词（摘要） | 系统提示词（摘要） |

**简记**：Rules = "**改这里要注意什么**"；Skill = "**这类任务怎么做**"；Agent = "**派个人独立去做**"。
