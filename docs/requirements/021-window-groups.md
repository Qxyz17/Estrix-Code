## 背景

AI 网页版（如 DeepSeek）在**操作频繁**时会限流，导致对话中断。
用户往往有**多个账号**（= 多个窗口，每个窗口独立 partition / 登录态）。
与其干等限流恢复，不如**换一个账号继续**。

本需求做**窗口组**：把多个窗口编成一组，限流时**分享当前对话给组内下一个窗口**，用新账号继续。

## 目标（半自动版）

先做**手动切换**，跑通核心链路，验证可行性；自动化（限流触发、探测轮换）留待下阶段。

### 范围

- ✅ 窗口组数据层（`window-groups.json`）
- ✅ 「窗口」页按组显示 + 编组 UI
- ✅ 组上「切换」按钮（手动触发切换链路）
- ✅ 切换链路：停止 → 分享 → 下一个窗口打开 → 初始化 → 继续
- ❌ 暂不做：探测目标窗口、限流自动触发、循环轮换

> **实际交付（2026-10-05）**：以上"暂不做"的**三项也已完成**——
> 探测轮换（P3b）、限流自动触发（P3a）、失败恢复重试（P3c）均已实现；
> 手动切换与自动切换**共用同一链路**（停止 → 分享 → 探测轮换 → 导航 → 初始化 → 焦点切换）。
> 另加 UI：新建组按钮、管理弹窗（改名 + 增删窗口）、组内"最近对话"可点击跳转。

## 设计（30 个确认点）

### 数据层

- **独立文件** `window-groups.json`（不污染 `profile-list.json`）
- 组结构：`{ id, name, windowIds: [按添加顺序], lastWindowId, lastSessionId }`
- **一个窗口只属于一个组**
- `lastWindowId` / `lastSessionId`：记录**最后一次继续的窗口与对话**（方便后续定位最新进展）
- **不挂会话血缘**（跨窗口记 `parentId` 改动太大）

### UI（「窗口」页）

- 窗口**按组分组显示**（未分组归"未分组"）
- 窗口上「**加入组**」：选已有组 / 新建组（**组随第一个加入的窗口自动创建**）
- **组标题上一个「切换」按钮**（组级操作）
- **配置组时提示**：组内窗口会被轮换打断
- 轮换顺序 = **按添加进组的顺序**（不提供拖拽排序）

### 切换触发（手动）

- 按钮挂在**组上**；点击 = 把**当前活跃窗口**切到**组里的下一个**
- **前置校验**：当前活跃窗口必须属于该组（否则提示）
- **无开关**：属于组即可切（编组即表达"这组要轮换"）

### 切换链路（点击后）

1. **停止当前窗口工具调用**（复用 `harness-stop`：发信号 + 点网页停止）
2. **创建分享**（当前活跃窗口的**当前对话全部消息**；**在源窗口页面执行**）
3. 找组里**下一个窗口**（按添加顺序；**复用已打开的**，未开则新建）
4. 下一个窗口**导航到分享链接**
5. **初始化项目**（**指定项目地址**；**不追加"请继续"**，让 AI 看到历史后自己续）
6. **焦点切到新窗口**
7. 记录 `lastWindowId` / `lastSessionId`

### 边界

- **原窗口保持打开**（后台待命，不关）
- **切换前停掉原窗口的自动重试**（避免双跑）
- **任一步失败 → 退回原窗口继续重试**（统一兜底）
- **分享只含当前会话**（不含更早的压缩历史；当前会话已含足够上下文）

## 下阶段（自动化）

- **探测目标窗口**：URL 参数（如 `?estrix-probe=1`）触发 → 新开对话发消息 → 复用 `onAiError`/`onInterceptedResponse` 判限流
- **限流自动触发**：`retry.ts` 检测到限流 → 先探测 B → 通则切换 → 不通探 C → 全不通退回重试
- **循环轮换**：A→B→C→A；都限流则退回重试（在**原窗口**等）
- **全自动**（无确认）+ 状态栏显示进度
