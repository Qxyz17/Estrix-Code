# Estrix Code 重构目标

> 状态：已确认 v1.0（2026-09-18）
> 本文件回答"为什么重构"，其余文档回答"怎么重构"。

---

## 1. 最终目标

**把 Estrix Code 迁移到 TypeScript，并完成模块化重构。**

两个目标的关系：
- **模块化**是主目标 —— 每个模块各司其职，边界清晰，功能不混淆。
- **TypeScript** 是手段 —— 作为重构的安全网与契约。

## 2. 要解决的问题

### 核心痛点：功能混淆
- 现状按 Electron 技术层分目录（`src/main` / `src/preload`），
  导致 `preload/dom/` 里"桥接逻辑"与"UI"混杂。
- 没有依赖规则，谁都能引用谁 → `state.js` 成杂物篮、
  `events.js`（813 行）又管界面又管业务。

### 具体表现（调研事实）
1. **两套工具并存**：`file_*` 与无前缀各一套，共 4 条路径（JSON×JS 两种模式）。
2. **工具名 3 处维护**：`tools/index`、`tool-names.js`、`JsRunner` 沙箱。
3. **已在漂移**：`tool-names.js` 漏了 `mcp_call`（潜在 bug）。
4. **巨型文件**：`events.js`(813) / `template.js`(526) / `deepseek.js`(572) / `index.js`(578)。
5. **提示词组织混乱**：`src/prompt/` 四份，实际只有两类，且有冗余。

## 3. 成功标准

重构完成后应达到：
1. **目录按领域分**（app / session / bridge / overlay / tools / providers / infra），
   依赖单向、无循环，由 ESLint 强制。
2. **全部源码为 TypeScript**，`strict` 通过。
3. **工具规范单一来源** —— 改工具即改规范，不再三处同步。
4. **一种调用模式**（JS），名字统一。
5. **provider 单文件自包含**，内置与自定义结构一致，统一实现接口。
6. **测试全绿**，关键路径有覆盖。
7. **行为不回归** —— 应用可正常启动、工具可正常调用。

## 4. 约束

- **个人独立开发**（D10）：不冻结 master，灵活优先。
- **零构建优点要保住**（D15）：不引入运行时 TS 编译器。
- **可接受破坏性升级**（D4/D15）：不兼容老的 JS provider、老的工具别名。
- **测试基础设施已完善**（285 个测试）：重构全程必须保持全绿。

## 5. 非目标（本次不做）

- 不改 IPC 通道命名（D6）。
- 不引入前端框架（overlay 保持纯 DOM）。
- 不做"老会话运行时兼容"（D3/D4）—— 老调用直接报错 + 提示新用法。
- 不追求一次性完成 —— 分 P0–P5 六阶段，每阶段可暂停。

## 6. 参考

- 上游参考项目：`deepseek-harness2`（dsh）—— 参考其工具目录生成、
  版本不匹配明确拒绝、迁移用独立脚本的做法。

## 7. 时间预期

**不设固定期限**（用户决定）。个人独立开发，按节奏推进，
质量优先于速度，不给自己 deadline。

每阶段结束是可交付点，可随时暂停。
