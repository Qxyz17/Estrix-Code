# Agents（子代理）配置与使用

> Agent 让主对话把任务**委派**给独立上下文的子代理，只回摘要。对齐 Claude Code 的 subagents 机制。

## 一、它是什么

代理是一个带 frontmatter 的 `.md` 文件，放在约定目录下。应用启动（初始化项目）时**自动扫描**，把代理的 **name + description** 注入系统提示词（**渐进式披露**）。

主对话判断任务适合委派时，用 `runAgent(name, task)` 调用。子代理在**独立上下文**（新窗口、共享登录态）中完成，**只把结果摘要返回**主对话——既隔离上下文（缓解长对话卡顿），又支持专门化 + 工具限制。

## 二、目录约定

| 作用域 | 路径 | 说明 |
|---|---|---|
| **项目级** | `<项目根>/.estrix/agents/<name>.md` | 随仓库走，团队共享 |
| **用户级** | `~/.estrix/agents/<name>.md` | 所有项目通用 |

- 直接扫 agents 目录下的 `.md` 文件（一层）
- **同名时项目级优先**（覆盖用户级）

## 三、代理文件格式

```markdown
---
name: code-reviewer
description: 审查代码质量。写完代码后使用。
tools: read, grep, glob
maxTurns: 20
---

你是资深代码审查专家。审查指定代码，找出真问题并给出建议。

## 关注点
1. 正确性
2. 安全
3. 可维护性
```

### frontmatter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 否 | 代理名。缺省取**文件名** |
| `description` | 否 | 何时委派给它。缺省取正文首段。**留空则代理被跳过** |
| `tools` | 否 | 允许使用的工具（逗号分隔）。缺省 = 全部 |
| `maxTurns` | 否 | 最大轮数（1~1000），防无限循环。缺省 = 无限制 |

## 四、如何生效

1. **初始化项目时自动扫描**——把代理清单注入系统提示词
2. 主对话看到「可用子代理」章节后，可自行判断委派

> 与技能不同，代理**没有**手动"重新发送"按钮——重启 / 重新初始化即可刷新。

## 五、完整示例

用户级 `~/.estrix/agents/explore.md`：

```markdown
---
name: explore
description: 只读探索代码库：大范围搜索、定位、分析代码结构。不修改任何文件。
tools: read, readLines, glob, grep
---

你是代码库探索专家。只读分析，**绝不修改文件**。

## 工作方式
- 先用 glob/grep 了解结构，再深入读关键文件
- 输出精炼的结论（它会作为摘要返回主对话）

## 输出格式
- 结论先行
- 关键位置：文件:行号
- 不确定处标注
```

## 六、与 Skills 的区别

| | Skill | Agent |
|---|---|---|
| **本质** | 当前上下文里的**流程 / 知识** | **独立上下文**的子对话 |
| **调用方式** | AI 自己 `read` SKILL.md | `runAgent(name, task)` 委派 |
| **上下文** | 复用主对话 | 全新独立 |
| **适用** | 规范、流程、脚本 | 大范围搜索、独立子任务 |

## 七、内置示例

项目自带 8 个代理：

| 作用域 | 代理 |
|---|---|
